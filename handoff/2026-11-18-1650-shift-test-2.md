## 🐞 1. «Геолокация выключена» срабатывает только при открытии приложения
В базе три пары `location_off` → `location_on`: 16:31:14→16:31:26, 16:33:42→16:34:07, 16:37:39→16:37:44. Паузы по 5–25 сек — то есть `location_off` пишется **в момент, когда Даниил открывает приложение**, и почти сразу он включает гео из диалога.
Со слов Даниила: **в фоне ничего не приходит** — ни напоминание рабочему, ни `location_off` бригадиру, — ни со свёрнутым, ни со смахнутым приложением. Приходит только при повторном открытии.

Почему (предположение): с выключенным гео служба не получает координат → JS-задача не просыпается; фоновая задача (BackgroundFetch/TaskManager) на Samsung раз в 15 мин не гарантирована и, похоже, не запускается вовсе.

Предлагаю:
- **Нативно ловить переключение гео:** `BroadcastReceiver` на `android.location.PROVIDERS_CHANGED` (небольшой Expo-модуль на Kotlin / config plugin). Он срабатывает сразу, даже в фоне, и может (а) показать локальное уведомление рабочему, (б) отправить `location_off_since` в Supabase прямым HTTP-запросом (токен из secure storage), не дожидаясь JS.
- Если нативный модуль сейчас дорог — хотя бы проверь, приходит ли в задачу `expo-location` событие с ошибкой / `LocationAvailability=false` при выключении гео, и реагируй на него.
- **Подстраховка уже есть** — `no_signal` через 20 мин. Но проверь, что **пульс в боевом режиме не зависит от случайных проверок**: сейчас `last_seen_at` совпадает с временем проверок (16:42:53 → 16:42:55). Если в боевом режиме пульс шлётся только при проверке раз в 60–120 мин, cron будет давать **ложные `no_signal`** каждые 20 мин. Пульс должен уходить на каждом пробуждении службы (раз в ~5 мин), а при выключенном гео — хотя бы из нативного ресивера/таймера.

## 🐞 2. Смахнули приложение — что с фоном?
Даниил подозревает, что после смахивания из недавних ничего не работает. Проверь отдельно: смахнуть → подождать 10 мин в тестовом режиме → есть ли проверки в `location_pings`. Если нет — служба не переживает swipe (на Samsung это частая история; `stopWithTask=false` у foreground service?).

## 🐞 3. Красная «1» на иконке приложения всю смену
Samsung показывает бейдж от постоянного уведомления «You're on shift» — убрать его нельзя, и выглядит как непрочитанное. Нужен канал уведомлений для foreground service с **`showBadge: false`** (и для напоминаний, если это отдельный канал — по вкусу). Если `expo-location` создаёт канал сам и не даёт настроить — создать канал с тем же id заранее через `expo-notifications` `setNotificationChannelAsync({ showBadge: false })` или через config plugin.
