# Field CRM — контекст проекта

Отвечай по-русски. Разработчик — Даниил, full-stack middle (JS/React/SQL), **мобилку делает впервые**: объясняй мобильные вещи (Expo, сборки, разрешения, фон) подробно. PHP не использовать.

## Что строим
MVP для американской строительной компании (первый клиент — Сергей Лазарев, дальше рынок, будут показы инвесторам).
Интерфейс приложения и CRM — **на английском**.

- **CRM (веб, `crm/`)** — для бригадира, работает с ПК и телефона.
- **Мобилка (`mobile/`)** — для рабочих. Сначала **Android**, iOS вторым этапом.
- Роли в MVP только две: `foreman` и `worker`.

## Стек
- `crm/`: React + Vite + TypeScript (TypeScript закреплён на ~6.0 — typescript-eslint пока не поддерживает 7.x).
- `mobile/`: Expo **SDK 57** (под Expo Go), TypeScript, expo-router по желанию.
- Бэкенд: Supabase (Postgres, Auth, Storage, Realtime, Edge Functions). Свой сервер не пишем.
  Проект на **новых ключах**: в клиентах используется publishable key (`sb_publishable_...`) — он подставляется туда, где в доках написано anon key. Legacy anon/service_role не используем.
- `shared/types.ts`: общие типы и утилиты (`distanceM`, `nextPingDelayMs`), импорт относительным путём.

## Функционал MVP (ядро, 2 недели)
1. Бригадир: объекты (адрес, координаты, радиус), аккаунты рабочих (логин+пароль через Edge Function `create-worker`), справочник материалов, задачи на день с выделенными материалами.
2. Рабочий: список задач на день → фото «до» → «In progress» с геолокацией. **Вне радиуса старт запрещён** (база кидает `NOT_ON_SITE`).
3. Во время смены: проверка геолокации в **случайный момент раз в 60–120 минут** (foreground service с уведомлением «You're on shift»). Вне объекта → локальное уведомление «You left the site», рабочий подтверждает и указывает, через сколько вернётся → бригадиру уведомление. Нет ответа → `no_response`, бригадир решает, вычитать ли время (`deduct`).
4. Финиш: «Work done» → фото/видео «после» с **водяным знаком** (время + координаты), фактический расход материалов (видно, сколько выделено). Свой материал вне справочника → `pending`, бригадир подтверждает.
5. Офлайн-режим: всё копится локально и синкается при сети; время сверяется с серверным.
6. CRM: уведомления в реальном времени, экспорт в Excel.

Геолокация собирается **только** между стартом и финишем смены, при первом входе — согласие.

**Неделя 3:** зарплата (дневная/почасовая ставка, овертайм x1.5 > 40 ч/нед; в Калифорнии и дневной), сводки день/неделя/месяц, карта бригадира, комментарии к задачам.

При нехватке времени первыми режем водяной знак и офлайн.

## Правила
- Схему меняем **только новыми миграциями** (`0004_...sql`), старые не правим.
- Ключ `service_role` — только в Edge Functions, никогда в `crm/` или `mobile/`.
- `.env*` не коммитим.
- Фоновая геолокация не работает в Expo Go: для неё development build (`npx expo run:android` или `eas build -p android --profile preview`).
