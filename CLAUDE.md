# Field CRM — контекст проекта

Отвечай по-русски. Разработчик — Даниил, full-stack middle (JS/React/SQL), **мобилку делает впервые**: объясняй мобильные вещи (Expo, сборки, разрешения, фон) подробно. PHP не использовать.

## Что строим
MVP для американской строительной компании (первый клиент — Сергей Лазарев, дальше рынок, будут показы инвесторам).
Интерфейс приложения и CRM — **на английском**.

- **CRM (веб, `crm/`)** — для бригадира, работает с ПК и телефона.
- **Мобилка (`mobile/`)** — для рабочих. Сначала **Android**, iOS вторым этапом.
- Роли в MVP только две: `foreman` и `worker`.

## Стек
- `crm/`: React + Vite + TypeScript (TypeScript закреплён на ~6.0 — typescript-eslint пока не поддерживает 7.x).
- `mobile/`: Expo **SDK 57** (под Expo Go), TypeScript, expo-router по желанию.
- Бэкенд: Supabase (Postgres, Auth, Storage, Realtime, Edge Functions). Свой сервер не пишем.
  Проект на **новых ключах**: в клиентах используется publishable key (`sb_publishable_...`) — он подставляется туда, где в доках написано anon key. Legacy anon/service_role не используем.
- `shared/types.ts`: общие типы и утилиты (`distanceM`, `nextPingDelayMs`), импорт относительным путём.

## Функционал MVP (ядро, 2 недели)
1. Бригадир: объекты (адрес, координаты, радиус), аккаунты рабочих (логин+пароль через Edge Function `create-worker`), справочник материалов, задачи на день с выделенными материалами.
2. Рабочий: список задач на день → фото «до» → «In progress» с геолокацией. **Вне радиуса старт запрещён** (база кидает `NOT_ON_SITE`).
3. Во время смены: проверка геолокации в **случайный момент раз в 60–120 минут** (foreground service с уведомлением «You're on shift»). Вне объекта → локальное уведомление «You left the site», рабочий подтверждает и указывает, через сколько вернётся → бригадиру уведомление. Нет ответа → `no_response`, бригадир решает, вычитать ли время (`deduct`).
4. Финиш: «Work done» → фото/видео «после» с **водяным знаком** (время + координаты), фактический расход материалов (видно, сколько выделено). Свой материал вне справочника → `pending`, бригадир подтверждает.
5. Офлайн-режим: всё копится локально и синкается при сети; время сверяется с серверным.
6. CRM: уведомления в реальном времени, экспорт в Excel.

Геолокация собирается **только** между стартом и финишем смены, при первом входе — согласие.

**Неделя 3:** зарплата (дневная/почасовая ставка, овертайм x1.5 > 40 ч/нед; в Калифорнии и дневной), сводки день/неделя/месяц, карта бригадира, комментарии к задачам.

При нехватке времени первыми режем водяной знак и офлайн.

## Фон и уведомления — РАБОТАЕТ, НЕ ПЕРЕДЕЛЫВАТЬ
Проверено на Galaxy S22 (Android, Samsung) 18.11.2026, коммиты `ca486dc` + `14ab363`. Уведомления о выключенной геолокации приходят и при **свёрнутом**, и при **смахнутом из недавних** приложении. Не заменять эту схему другими подходами (другие библиотеки фона, headless JS, WorkManager вместо службы и т.п.) без явной просьбы Даниила и повторной проверки на телефоне. Новое — только добавлять поверх.

Как устроено (всё нужно, части страхуют друг друга):
1. **Служба смены** — `expo-location` `startLocationUpdatesAsync` с `foregroundService` и `killServiceOnDestroy: false` (`mobile/src/geo/shiftTracking.ts`). Держит процесс живым, в том числе после свайпа. Будит JS-обработчик раз в 5 мин (тестовый режим — раз в 1 мин): случайные проверки в `location_pings` + сердцебиение `last_seen_at` **на каждом пробуждении**, не только при проверке.
2. **Нативный модуль `shift-guard`** (`mobile/modules/shift-guard`, Kotlin, локальный Expo-модуль) — приёмник системной рассылки `PROVIDERS_CHANGED`. Нужен, потому что с выключенной геолокацией служба не получает точек и JS не просыпается (у `expo-location` точки идут через `PendingIntent`, события «геолокация недоступна» нет). Модуль **сам, без JS** показывает рабочему уведомление «Location is off» (id 7301, канал `location-off`) и снимает его при включении; событие `onLocationToggle` уходит в JS → `reportShiftHealth` → `work_sessions.location_off_since` → триггер шлёт бригадиру `location_off` / `location_on`.
3. **Фоновая задача** `expo-background-task` раз в ~15 мин (`shift-watch`) — запасной пульс и проверка разрешений.
4. **Сервер** — `pg_cron` каждые 5 мин: открытая смена без пульса > 20 мин → бригадиру `no_signal` (на случай, если процесс всё-таки убит или телефон выключен).
5. Канал уведомления службы `<package>:shift-location` создаёт `shift-guard` заранее с `showBadge: false` (иначе Samsung держит красную «1» на иконке всю смену).

Ограничения, которые обходить не надо: постоянное уведомление «You're on shift» в этом SDK не поддерживает кнопки и смену текста (у `expo-location` только title/body/color); фоновая задача Android — не чаще раза в 15 мин.

## Правила
- Схему меняем **только новыми миграциями** (`0004_...sql`), старые не правим.
- **Тексты интерфейса — только через ключи i18n**, не строками в коде: `t('раздел.ключ')` в компонентах, `i18n.t(...)` вне React (уведомления, фоновые задачи). Новый текст — сначала в `en.json`. Ключи типизированы: опечатка в ключе — ошибка `tsc`. Даты и время — через `formatTime` / `formatShortDate` (мобилка) с языком приложения, без `'en-US'`.
- **Цвета — только токены темы**, не hex в экранах. Мобилка: `mobile/src/lib/theme.tsx` (палитры light/dark, общие стили `ui`, `useTheme()`, `useThemedStyles(createStyles)`); CRM: CSS-переменные в `crm/src/index.css` (`:root` и `:root[data-theme='dark']`). Новый цвет — сначала в обе палитры, с проверкой контраста ≥ 4.5:1. Палитры мобилки и CRM по смыслу одинаковые.
- Нативный код своих модулей лежит в `mobile/modules/<имя>/android/` и **коммитится**; игнорируется только сгенерированный `mobile/android/`.
- Ключ `service_role` — только в Edge Functions, никогда в `crm/` или `mobile/`.
- `.env*` не коммитим.
- Supabase на Free **засыпает после 7 дней без активности**: «ничего не работает» после перерыва — сначала проверить, отвечает ли `<ref>.supabase.co` (у спящего проекта адрес пропадает из DNS), и восстановить в панели.
- Android-сборка — на **JDK 17** (`C:\Program Files\Microsoft\jdk-17.0.21.21-hotspot`). На JDK 25 из Android Studio падает шаг CMake (`configureCMakeDebug`).
- Фоновая геолокация не работает в Expo Go: для неё development build (`npx expo run:android` или `eas build -p android --profile preview`).
